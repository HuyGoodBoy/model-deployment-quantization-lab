02 / Thử bằng tay

Một số thực trở thành INT8 thế nào?

q = clip(round(r / scale) + zero_point, −128, 127)
r̂ = scale × (q − zero_point)

Kéo thanh trượt để thấy rounding và clipping. Ví dụ dùng round ties-to-even như numpy.rint trong code.

Scale nhỏ → bước lượng tử nhỏ hơn, nhưng dải giá trị hẹp hơn. Calibration giúp chọn dải phù hợp với activation thực tế.

03 / Đọc đúng tên

Quantization có nhiều mức độ.

DYNAMIC

Weights và activation theo runtime

ONNX dynamic tính scale activation khi chạy các op được hỗ trợ. Thường phù hợp Transformer nhiều MatMul. TFLite dynamic range là chiến lược riêng, phải xem graph thực tế.

STATIC INT8

Calibration trước inference

Dùng dữ liệu đại diện để đo range. CV thử full INT8 TFLite; ONNX dùng QDQ S8S8 per-channel weights. Transformer TFLite có thể còn float op: gọi mixed INT8.

FP16 WEIGHTS

Ít storage hơn

TFLite lưu weights float16. CPU có thể dequantize về FP32 khi load; tên FP16 không bảo đảm toàn bộ phép tính CPU là FP16.

PTQ không train lại model. QAT là hướng khác, đưa mô phỏng quantization vào training. Bài này đo PTQ; không dùng evaluation để chọn lại scale.
04 / Bằng chứng thực nghiệm

Nhỏ hơn, nhanh hơn và đúng hơn là ba câu hỏi riêng.

Biến thểMiBMedian msAccuracyTop-5 accuracyMAEMax errorSNR dBAgreement
Hiểu các metric output

MAE = trung bình |candidate − reference|. RMSE = căn trung bình bình phương error. Max error là lệch lớn nhất ở một phần tử. SNR = 10 log₁₀(Σreference² / Σerror²), càng cao càng gần model gốc; error bằng 0 thì SNR vô hạn.

Cosine đo hướng hai vector, gần 1 chưa bảo đảm độ lớn giống nhau. Accuracy là dự đoán đúng nhãn thật. F1 positive = 2TP / (2TP + FP + FN). Agreement là cùng nhãn dự đoán với model gốc: cả hai có thể cùng sai.

Báo cáo Markdown và JSON/CSV giữ đủ MAE, RMSE, max, cosine, relative L2, SNR, accuracy, F1/top-5 và agreement. So output thật sau dequantize, không renormalize để che sai khác.

Accuracy dựa nhãn thật; agreement dựa model gốc. SNR của CV tính trên probabilities, NLP tính trên logits: không so trực tiếp hai SNR như cùng bài toán. Các số đo mô tả PC CPU của lượt này, chưa phải kết quả Android.

05 / Vừa học vừa làm
Chạy từng bước. Đọc từng phần.
Quy trình
1
Download & prepare
Pin revision/hash → chọn dữ liệu có nhãn → preprocessing/tokenization → tách calibration/evaluation.
2
Export & quantize
Xuất FP32 → xác minh baseline → tạo biến thể → audit dtype/operator, giữ lại lỗi nếu không hỗ trợ.
3
Evaluate & benchmark
Lưu full output → MAE/SNR/accuracy → 30 warm-up, 200 lượt đo, process riêng cho mỗi biến thể.
4
Verify & package
Tính lại từ raw results → báo cáo → ZIP theo allowlist → kiểm tra bản giải nén.
Lệnh chạy từ thư mục bài lab
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe run_lab.py
Lần đầu cần Internet tải weights và dataset. ZIP chứa kết quả và code; các model/dataset lớn được tải lại từ nguồn có checksum.
Kiểm chứng kết quả đã bàn giao, offline
.\.venv\Scripts\python.exe -m qlab.verify
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Verifier chỉ cần NumPy và Pillow; không tải hoặc chạy lại model. Xem README để biết môi trường và lệnh cho từng stage.
